# 安全事件响应 Runbook

## 1. 分级与时限

| 级别 | 示例 | 首次响应 | 升级 |
| --- | --- | --- | --- |
| SEV-1 | 跨用户数据泄露、凭证泄露、审计被篡改、重复高额副作用 | 15 分钟 | 安全负责人 + 技术负责人 + 合规 |
| SEV-2 | 单租户越权尝试、Provider 认证持续失败、Sandbox 逃逸告警 | 30 分钟 | 安全值班 + 服务负责人 |
| SEV-3 | 可疑扫描、孤立告警、低风险配置偏差 | 4 小时 | 当班工程师 |

## 2. 立即处置

1. **止损**：按 [密钥轮换与吊销](key-revocation.md) 吊销泄露密钥、撤销刷新令牌族、禁用受影响 Provider/MCP 或用户。
2. **隔离**：必要时摘除异常实例或封禁来源 IP；禁止直接删除审计与日志证据。
3. **保留证据**：记录时间线、TraceID、RunID、审计事件、镜像 digest 与配置版本；导出前先做脱敏。
4. **确认影响面**：按 `user_id`、`tenant_key`、`session_id` 聚合审计与 Outbox；区分已确认泄露与疑似。
5. **恢复服务**：修复根因并验证跨用户隔离、审计链和重复副作用后才解除封禁。

## 3. 常见场景

| 场景 | 处置要点 |
| --- | --- |
| JWT 泄露 | 移除旧 `kid` 并滚动重启；必要时提升用户 `credential_version` |
| 刷新令牌重用 | 整族撤销；检查同一族的登录 IP/设备与审计 |
| Provider 凭证泄露 | 轮换 Provider 密钥并重存凭据；检查模型调用费用异常 |
| 飞书签名伪造 | 拒绝事件并告警；核对 `event_id` 幂等与死信，不重放可疑载荷 |
| 审计链断链 | 停止相关写入，按 Hash Chain/Checkpoint 定位断点；禁止修补历史行 |
| 跨用户读取 | 立即封禁相关接口/账号，复跑 RLS 集成测试与 DAST 权限探测 |

## 4. 通知与复盘

- SEV-1/SEV-2 在止损后 1 小时内通知用户与合规负责人；通知内容不包含其他用户数据。
- 事件关闭后 5 个工作日内完成复盘，使用 [复盘模板](postmortem.md)；纠正措施必须有负责人和截止日期。
- 所有处置动作写入审计；无法自动写入时由操作者补录并注明来源与原因。
