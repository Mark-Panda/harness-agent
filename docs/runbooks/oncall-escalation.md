# 值班与升级 Runbook

## 1. 值班职责

- 首响：确认告警真实性、影响范围与最近变更，避免盲目重启。
- 记录：在事件频道记录开始时间、影响接口/用户、TraceID、处理动作与当前状态。
- 升级：达到时限或影响扩大时按下方路径升级，不等待自行排查完成。

## 2. 升级路径

| 条件 | 升级对象 | 方式 |
| --- | --- | --- |
| Critical 告警持续 10 分钟未缓解 | 服务负责人 | 电话 + 事件频道 |
| 数据损坏/越权/重复副作用 | 安全负责人 + 技术负责人 | 立即电话升级 |
| 依赖（PostgreSQL/Redis/Provider/飞书）持续不可用 | 平台负责人 + 供应商支持 | 事件频道 + 工单 |
| 错误预算 1 小时燃烧率 ≥ 14.4 倍 | 技术负责人 | 冻结非必要发布 |
| 需要回滚但审批人不可达 | 发布负责人 + 备份审批人 | 按预先授权名单 |

## 3. 关键指标入口

- 健康：`/health/live`、`/health/ready`、`/api/v1/health`
- 告警与 SLO：[告警 Runbook](harness-agent-alerts.md)
- 故障降级：[故障注入与降级](failure-degradation.md)
- 发布与回滚：[滚动发布](rolling-deployment.md)、[预发布验收](release-acceptance.md)
- 安全事件：[安全事件响应](security-incident.md)

## 4. 交接清单

- 当前未关闭告警、已采取动作与待观察指标。
- 在途 Run、队列积压、Outbox 失败与 SSE 连接数。
- 最近发布版本/digest、迁移版本与是否 dirty。
- 任何临时绕过、封禁或手工补录操作及其到期时间。

## 5. 禁止事项

- 禁止删除审计日志、跳过签名校验或直接修改生产数据库来“消除告警”。
- 禁止在未确认根因时反复重启或扩大重试，避免放大外部依赖故障。
- 禁止口头豁免阻断项；所有豁免必须有书面记录、负责人和到期时间。
